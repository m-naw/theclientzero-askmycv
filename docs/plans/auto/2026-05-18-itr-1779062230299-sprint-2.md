# Sprint Plan: Feature Changes and Verification

**Sprint ID:** ITR-1779062230299-sprint-2
**Spec:** [2026-05-17-foundation-config-schema-theme-system-system-prompt-seo-accessibility-baseline.md](docs/specs/auto/2026-05-17-foundation-config-schema-theme-system-system-prompt-seo-accessibility-baseline.md)
**Confidence:** 0.9

## Context

Sprint 2 of G2 goal: applies feature-level changes on top of the Sprint 1 design-system layer (already committed). Adds admin_password + theme to setup form, appends plain-text instruction to system prompt, adds role=log to chat message container, and verifies the full toolchain passes with >=214 tests.

## Risk flags

- RF1: No select() primitive exists in src/views/primitives/ — theme select must use inline HTML template literal matching the pattern already used for the model select in advancedFields (setup-form.ts:103-110). Executor must not attempt to import a non-existent primitive.
- RF2: parseStoredConfig() uses a cast (`r as unknown as StoredConfig`) for optional fields not explicitly validated — adding theme and admin_password_hash to the StoredConfig interface is non-breaking and requires no validator update. If a prior goal added strict validation for all interface fields, typecheck in T-2 will surface this; executor should not preemptively add validation logic.

## Task T-1: Implement Sprint 2 feature changes: setup-form fields, system prompt clause, chat-page accessibility, config schema

**Type:** code (modelTier: 2)

**Files to modify:**
- src/views/setup-form.ts (workspace: primary)
- src/prompts/system.ts (workspace: primary)
- src/views/chat-page.ts (workspace: primary)
- src/types/config.ts (workspace: primary)

### Step 1

In src/views/setup-form.ts, add two optional fields to the SetupFormFields interface after the existing 'model?' field:
  admin_password?: string;
  theme?: 'light' | 'dark';
This satisfies the interface-level schema requirement without breaking existing callers.

**File reference:** src/views/setup-form.ts
**Verification:** grep -P 'admin_password' src/views/setup-form.ts exits 0 AND grep -P 'theme' src/views/setup-form.ts exits 0

### Step 2

In src/views/setup-form.ts, add a theme select and admin_password input to the requiredFields array inside renderConfigForm(). Insert them after the existing anthropic_api_key input and before the cv_markdown textarea. Use inline HTML template literals (same pattern as the model select in advancedFields) since no select() primitive exists:

For theme (add as first item in requiredFields or after display_name):
```
`<label class="field">
  <span class="field-label">Theme</span>
  <select class="input" name="theme" required>
    <option value="light"${(p.theme ?? 'light') === 'light' ? ' selected' : ''}>Light</option>
    <option value="dark"${p.theme === 'dark' ? ' selected' : ''}>Dark</option>
  </select>
</label>`
```

For admin_password (add after theme or after anthropic_api_key):
```
input({
  name: 'admin_password',
  label: 'Admin password',
  type: 'password',
  required: true,
  hint: '12–128 characters',
  autocomplete: 'off',
})
```

Both must be inside the requiredFields array so they render in the Required section.

**File reference:** src/views/setup-form.ts
**Verification:** grep -P 'name="admin_password"' src/views/setup-form.ts exits 0 AND grep -P 'name="theme"' src/views/setup-form.ts exits 0

### Step 3

In src/prompts/system.ts, append clause (f) to the BEHAVIORAL_INSTRUCTIONS constant string after the existing clause (e). The clause must contain the literal substrings 'plain text' and 'no markdown'. Append before the closing backtick of the template literal:

```
(f) Reply in plain text only — no markdown syntax. Do not use headings (#), bullet dashes (*), asterisks for bold (**), backtick code fences, or any other markdown formatting. Visitors read responses as plain text; markdown characters appear literally and harm readability.
```

**File reference:** src/prompts/system.ts
**Verification:** grep -i 'plain text' src/prompts/system.ts exits 0 AND grep -i 'no markdown' src/prompts/system.ts exits 0

### Step 4

In src/views/chat-page.ts, at line 46, add role="log" to the message-list section element alongside the existing aria-live="polite". Change:
  <section class="message-list" aria-live="polite" aria-label="Conversation"></section>
To:
  <section class="message-list" role="log" aria-live="polite" aria-label="Conversation"></section>

**File reference:** src/views/chat-page.ts
**Verification:** grep -r 'role="log"' src/views/ exits 0

### Step 5

In src/types/config.ts, add theme and admin_password_hash optional fields to the StoredConfig interface after the existing optional fields section (after 'accent_color?'):

  /** UI color scheme. Optional; defaults to 'light'. */
  theme?: 'light' | 'dark';
  /** Bcrypt/argon2id hash of the admin password. KV-only; never echoed. */
  admin_password_hash?: string;

No change to parseStoredConfig() is required — optional fields fall through the existing `r as unknown as StoredConfig` cast, and the validator only checks named required and optional-with-rules fields.

**File reference:** src/types/config.ts
**Verification:** grep -P 'admin_password_hash' src/types/config.ts exits 0 AND grep -P 'theme.*light.*dark' src/types/config.ts exits 0
