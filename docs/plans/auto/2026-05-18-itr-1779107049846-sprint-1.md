# Sprint Plan: Login Form + Redirect Fixes

**Sprint ID:** ITR-1779107049846-sprint-1
**Spec:** [2026-05-18-checkpoint-auth-security-review-remediation-2.md](docs/specs/auto/2026-05-18-checkpoint-auth-security-review-remediation-2.md)
**Confidence:** 0.85

## Context

G4 remediation round 3: adds /login route and form, fixes POST /setup redirect to /, replaces bare "Login required" text with redirect to /login, and adds login-flow integration test.

## Risk flags

- RF1: Session cookie Path=/admin (set in src/auth/session.ts:163) means browsers do NOT send the cookie to GET /. Integration test step 3 works because the test manually sets the Cookie header. Real-browser login via POST /login → 303 / is correct because GET / is public when config exists — no session needed for chat page. No code change required, but executor must not change buildSetCookieHeader Path unless explicitly directed.
- RF2: Bootstrap-state check in handleRoot must run AFTER detectState() to avoid extra KV reads on every request in the C_CONFIGURED path. The check is guarded by `result.state !== State.C_CONFIGURED`, so C_CONFIGURED requests skip the extra KV get entirely. Executor must preserve this guard.

### Step 2

Create src/routes/login.ts. Export handleGetLogin(request, env, ctx) and handlePostLogin(request, env, ctx). handleGetLogin: returns 200 HTML from renderLoginForm(). handlePostLogin: (a) parse form body for admin_password field; (b) read admin_password_hash from KV using ADMIN_PASSWORD_HASH_KEY (import from ../types/auth) — if null return 404; (c) call verifyPassword(adminPassword, hash) from ../auth/password; (d) if match: call createSessionCookie(env.STATE), emit console.log(JSON.stringify({event:'auth_decision',outcome:'success',route:'/login'})), return Response(null,{status:303,headers:{'Location':'/','Set-Cookie':cookie}}); (e) if no match: call delayWrongPassword(), emit console.log(JSON.stringify({event:'auth_decision',outcome:'fail',route:'/login'})), return 200 HTML renderLoginForm({error:'Invalid password'}). CRITICAL: Never cache admin_password_hash in module scope — always read from KV per request. HARD CONSTRAINT: Anthropic API key is never read or echoed in this file.

**File reference:** src/routes/login.ts
**Verification:** grep -n 'auth_decision' src/routes/login.ts && grep -n 'ADMIN_PASSWORD_HASH_KEY' src/routes/login.ts && grep -n 'createSessionCookie' src/routes/login.ts && grep -n 'Location.*/' src/routes/login.ts

Import renderLoginForm from ../views/login-form. This renders the login form when admin_password_hash is set but no config exists (bootstrap state) and no valid session cookie is present.

(2) 'POST /login with correct password returns 303 Location /': set KV admin_password_hash = testHash, also put KV cookie_signing_secret = 'test-secret-for-login-flow-32b!!'. (3) 'GET / with valid session cookie and config set returns chat UI': set KV admin_password_hash = testHash, cookie_signing_secret = 'test-secret-for-login-flow-32b!!', and config = JSON.stringify minimal valid StoredConfig (display_name:'Test',headline:'Test',cv_markdown: 'x'.repeat(100), anthropic_api_key:'sk-test', daily_budget_usd:5, setup_timestamp:Date.now(), model:'claude-haiku-4-5-20251001'). Mint a valid session cookie using signSession + buildSetCookieHeader (or reuse mintSessionCookie pattern from the setup test). GET https://example.test/ with Cookie header containing the session token. Assert status 200 and body does NOT contain 'Login required'.

IMPORTANT: Each test case must use a fresh KV state (use beforeEach to clear relevant keys or ensure isolation). Add afterEach to delete the keys set by each test: STATE.delete('admin_password_hash'), STATE.delete('config'), STATE.delete('cookie_signing_secret').
