# Sprint Plan: Setup Password Bootstrap — Remove Mandatory JWT, Add admin_password, Integration Test

**Sprint ID:** ITR-1779098374478-sprint-1
**Spec:** [2026-05-18-checkpoint-auth-security-review-remediation-1.md](docs/specs/auto/2026-05-18-checkpoint-auth-security-review-remediation-1.md)
**Confidence:** 0.88

## Context

G4 remediation: remove mandatory CF JWT gate from /setup, enable password-only bootstrap for BYOK self-hosting without Cloudflare Access

## Risk flags

- RF1: parseStoredConfig currently rejects absent OR empty-string access_email/aud/team_domain — the fix must handle both absent (undefined) and empty string cases when no CF JWT was present at setup time; empty strings stored by mistake would silently break admin access
- RF2: existing setup-acceptance.test.ts tests use JWT-based POST /setup flows — making JWT optional must preserve their behavior; specifically tests that DO supply a valid JWT must still capture identity claims into config
- RF3: machine.ts detectState C_CONFIGURED block currently returns access_denied whenever jwtValid is false, including for password-only setups where access_email is empty — the fix must short-circuit to C_CONFIGURED (no reason) when storedConfig.access_email is absent or empty, before any JWT check
- RF4: The new integration test must mock the Anthropic API call (via fetchMock + ANTHROPIC_BASE_URL) exactly as setup-acceptance.test.ts does — omitting this mock causes a live network call failure in the test runner

## Task T-1: Remove mandatory JWT gate from setup.ts; add admin_password + optional JWT + Set-Cookie; make access fields optional in config and machine

**Type:** code (modelTier: 3)

**Files to modify:**
- src/routes/setup.ts (workspace: primary)
- src/types/config.ts (workspace: primary)
- src/state/machine.ts (workspace: primary)

### Step 1

In src/routes/setup.ts, add import for hashPassword from '../auth/password' and createSessionCookie from '../auth/session'. These are needed for bcrypt hashing and session cookie creation on POST /setup success.

**File reference:** src/routes/setup.ts
**Verification:** grep -n 'hashPassword\|createSessionCookie' src/routes/setup.ts shows both imports

### Step 2

In src/routes/setup.ts handlePostSetup: replace lines 63-76 (unconditional JWT gate — the block that checks headerToken.length === 0 and returns 403 'missing cf-access-jwt-assertion header', plus the verifyAccessJwt try/catch that returns 403 on failure) with an optional JWT capture block. Pattern: attempt readAccessJwt + resolveJwksSource + verifyAccessJwt inside a try/catch; if header is absent (token.length === 0) or verification throws, set `identity = null` and continue. Only assign identity when verification succeeds.

**File reference:** src/routes/setup.ts:62-76
**Verification:** grep -n 'missing cf-access-jwt-assertion' src/routes/setup.ts | wc -l returns 0 inside the POST handler unconditional path

### Step 3

In src/routes/setup.ts handlePostSetup, after the existing form parsing block (after the cv_markdown bounds check and optional model/accent_color reads), add admin_password handling: read `admin_password` field from form, validate its length is between 12 and 128 chars inclusive (return errorResponse(400, 'admin_password must be 12–128 characters', 'admin_password') if outside range), then call `const admin_password_hash = await hashPassword(admin_password)`. The field is required — if empty, return 400.

**File reference:** src/routes/setup.ts:139-145
**Verification:** grep -n 'admin_password' src/routes/setup.ts shows reading, validation, and hashing in the POST handler

### Step 4

In src/routes/setup.ts handlePostSetup, update the StoredConfig object construction (currently lines ~169-181): when `identity !== null`, set access_email: identity.email, access_aud: identity.aud, access_team_domain: identity.team_domain; when identity is null, omit these fields entirely (do not set them to empty strings, to match the optional interface). Also add `admin_password_hash` to the config object using the value from step 3.

**File reference:** src/routes/setup.ts:169-181
**Verification:** grep -n 'admin_password_hash\|access_email\|identity' src/routes/setup.ts shows conditional assignment

### Step 5

In src/routes/setup.ts handlePostSetup success path (after env.STATE.put('config', ...) and before building the HTML response): call `const setCookie = await createSessionCookie(env.STATE)` and return the 200 response with headers `{ 'content-type': 'text/html; charset=utf-8', 'set-cookie': setCookie }` so the first admin session is established immediately after setup.

**File reference:** src/routes/setup.ts:183-201
**Verification:** grep -n 'createSessionCookie\|set-cookie\|Set-Cookie' src/routes/setup.ts shows cookie creation and header inclusion in 200 response

### Step 6

In src/routes/setup.ts handleGetSetup: replace lines 212-224 (unconditional JWT gate — token.length === 0 check returning 403, and verifyAccessJwt try/catch returning 403) with optional JWT capture using the same try/catch pattern: if absent or verification fails, set `identity = null`. Update the final renderSetupForm call to use `renderSetupForm({ email: identity?.email ?? '' })` — works with empty string since setup-form.ts already handles that case.

**File reference:** src/routes/setup.ts:211-246
**Verification:** grep -n 'missing cf-access-jwt-assertion' src/routes/setup.ts returns 0 lines total

### Step 7

In src/types/config.ts StoredConfig interface (lines 24-28): change `access_email: string` to `access_email?: string`, `access_aud: string` to `access_aud?: string`, `access_team_domain: string` to `access_team_domain?: string`. Update the JSDoc comments to say 'Optional — present only when CF Access JWT was verified during setup.'

**File reference:** src/types/config.ts:24-28
**Verification:** grep -n 'access_email\|access_aud\|access_team_domain' src/types/config.ts shows all three with ? optional marker

### Step 8

In src/types/config.ts parseStoredConfig (lines 96-108): remove 'access_email', 'access_aud', 'access_team_domain' from the `stringFields` const array. After the existing stringFields loop, add optional type checks: for each of ['access_email', 'access_aud', 'access_team_domain'], if the field is present (r[f] !== undefined), verify it is a string (typeof r[f] === 'string'); if not a string, return { ok: false, error: `field ${f} must be a string if present` }. Empty strings are allowed.

**File reference:** src/types/config.ts:96-108
**Verification:** grep -n 'access_email\|access_aud\|access_team_domain' src/types/config.ts shows no occurrence inside the stringFields array

### Step 9

In src/state/machine.ts StoredConfigIdentity interface (lines 70-74): change all three fields to optional: `access_email?: string`, `access_aud?: string`, `access_team_domain?: string`. Then in detectState C_CONFIGURED block (lines 109-131): replace the current unconditional JWT-absence check with a conditional one. New logic: (1) parse storedConfig; (2) if storedConfig.access_email is a non-empty string, then perform the existing JWT claim matching (jwtValid, email, aud, teamDomain checks); (3) if storedConfig.access_email is absent or empty string, skip JWT checking entirely and return { state: State.C_CONFIGURED } — session-cookie auth handles access for no-CF setups.

**File reference:** src/state/machine.ts:70-131
**Verification:** grep -n 'access_email' src/state/machine.ts shows optional field declaration and conditional JWT check guarded by non-empty access_email
