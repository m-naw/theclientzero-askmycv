## Task T-1: Update smoke tests for password-primary admin auth model

**Type:** code (modelTier: 2)

**Files to modify:**
- src/test/smoke.test.ts (workspace: primary)

### Step 1

Add import for `signSession` from `../auth/session` at the top of src/test/smoke.test.ts. This is needed to mint valid session cookies in tests without calling POST /admin/login.

**File reference:** src/test/smoke.test.ts
**Verification:** grep -n 'signSession' src/test/smoke.test.ts should show the import line

### Step 2

Inside the 'JWKS injection wired through Worker /admin route' describe block, add a constant `const TEST_SESSION_SECRET = 'smoke-test-cookie-signing-secret-ok';` and an async helper function `async function makeSessionCookie(kv: KVNamespace): Promise<string>` that: (a) writes TEST_SESSION_SECRET to kv under key 'cookie_signing_secret', (b) calls signSession({ sub: 'admin', iat: Math.floor(Date.now()/1000), exp: Math.floor(Date.now()/1000)+604800 }, TEST_SESSION_SECRET), (c) returns the string `askmycv_admin_session=${token}`.

**File reference:** src/test/smoke.test.ts
**Verification:** grep -n 'makeSessionCookie' src/test/smoke.test.ts should return at least 2 lines (definition + usage)

### Step 3

In the afterEach of 'JWKS injection wired through Worker /admin route', add `await kv.delete('cookie_signing_secret');` so the signing secret is cleaned up between tests.

**File reference:** src/test/smoke.test.ts
**Verification:** grep -n 'cookie_signing_secret' src/test/smoke.test.ts should show the delete call in afterEach

### Step 4

Update the first test ('Worker /admin accepts a valid JWT and rejects a forged one'): (a) call `const sessionCookie = await makeSessionCookie(kv);` after seeding config and JWKS in KV, (b) add `Cookie: sessionCookie` header to both the validRes request and the forgedRes request alongside the existing CF-Access-JWT-Assertion header. The expected statuses remain 200 and 403 respectively.

**File reference:** src/test/smoke.test.ts
**Verification:** grep -n 'Cookie.*sessionCookie\|sessionCookie.*Cookie' src/test/smoke.test.ts should show 2 occurrences (one per request)

### Step 5

Rewrite the second test to verify that a valid session cookie without a CF-Access-JWT-Assertion header returns 403 when config.access_email is set. New test body: (a) seed the same full config object (with access_email: 'owner@example.com') into KV, (b) call makeSessionCookie(kv) to get a session cookie, (c) make a GET /admin request with only the Cookie header (no CF-Access-JWT-Assertion), (d) assert status 403. Update the test description to 'Worker /admin returns 403 when access_email is set but CF-Access-JWT-Assertion header is absent'.

**File reference:** src/test/smoke.test.ts
**Verification:** grep -n '403' src/test/smoke.test.ts should show both the forged-JWT assertion and the missing-JWT assertion

### Step 6

Run pnpm test and confirm all tests pass with exit 0. If any tests still fail, read the error output and fix the root cause — do NOT proceed to commit with failing tests.

**File reference:** src/test/smoke.test.ts
**Verification:** pnpm test exits 0 with no failing tests
