## Context

Goal G3: Replace mandatory Cloudflare Access on admin routes with password-primary auth (bcryptjs cost=12, HMAC-SHA256 session cookies) while preserving optional CF Access as progressive enhancement. Sprint 1 covers the auth core only; Sprint 2 covers admin UX additions.

## Risk flags

- RF1: bcryptjs cost=12 in production hashPassword is intentionally slow (~300ms). Tests in src/__tests__/admin/admin-session.test.ts MUST use a pre-computed literal bcrypt hash at cost=4 rather than calling hashPassword() at test runtime to avoid vitest worker timeout. Document the plaintext alongside the hash constant in a comment.
- RF2: crypto.subtle.importKey for HMAC requires the secret as an ArrayBuffer — use new TextEncoder().encode(secret). base64url encoding must use btoa() with URL-safe character substitution (+ → -, / → _, strip =) since node:Buffer is not available in Workers V8 isolate even with nodejs_compat (btoa works on strings not Uint8Arrays — convert via String.fromCharCode spread first).
- RF3: All 5 existing tests in src/test/admin.test.ts will fail after the session-primary auth rewrite because they send JWT headers but no session cookie. T-2 step 7 MUST update these tests before pnpm test is run. Failing to do this blocks the entire test suite.
- RF4: handleAdminGet currently seeds the admin form with authResult.identity.email (from JWT). When access_email is empty and no CF Access check is performed, this email source disappears. The renderAdminForm call must use a fallback (e.g. config.display_name or empty string) or the TypeScript types will reject a missing required argument.
- RF5: vitest.config.ts uses defineWorkersConfig with singleWorker:true but no explicit include/exclude glob — all *.test.ts files under src/ should be picked up automatically. If src/__tests__/admin/admin-session.test.ts is not discovered, add 'include: ["src/**/*.test.ts"]' to the test config options.

### Step 2

Add exported function handleAdminLogin(request, env, _ctx). Steps: (1) Get IP from request.headers.get('CF-Connecting-IP') ?? '0.0.0.0'. (2) Call checkAndIncrement(env.STATE, ip, 10, new Date(), 'loginratelimit') — if !allowed return Response with status 429 and body 'Too Many Requests'. (3) Parse FormData; extract admin_password = form.get('admin_password') as string. (4) Load config via loadConfig(env) — if null, await new Promise(r => setTimeout(r, 500)), return 401. (5) If !config.admin_password_hash, await new Promise(r => setTimeout(r, 500)), return 401. (6) const ok = await verifyPassword(admin_password, config.admin_password_hash) — if !ok, await new Promise(r => setTimeout(r, 500)), return 401. (7) Ensure config.cookie_signing_secret exists: if absent, generate one via Array.from(crypto.getRandomValues(new Uint8Array(32))).map(b=>b.toString(16).padStart(2,'0')).join(''), write updated config back to KV. (8) Create payload JSON {sub:'admin',iat:Math.floor(Date.now()/1000),exp:Math.floor(Date.now()/1000)+604800}. (9) token = await signSession(JSON.stringify(payload), config.cookie_signing_secret). (10) Return Response with status 200, Set-Cookie header = buildSessionCookie(token).

**File reference:** src/routes/admin.ts
**Verification:** grep 'setTimeout(r, 500)' src/routes/admin.ts exits 0

### Step 3

Add exported function handleAdminReset(request, env, _ctx). Steps: (1) Load config — if null, return 403. (2) Verify session: token = readSessionToken(request); if token is empty or !(await verifySession(token, config.cookie_signing_secret ?? '')).valid, return 403. (3) Parse FormData; extract confirm field. (4) If confirm !== 'DELETE ALL CONFIG', return Response with status 400 JSON {error:'confirm must be exactly DELETE ALL CONFIG'}. (5) Delete KV keys: await Promise.all(['config','secrets','admin_password_hash','cookie_signing_secret','setup_window_start'].map(k => env.STATE.delete(k))). (6) Return Response with status 200, Set-Cookie header = clearSessionCookie(), body 'Configuration deleted. Redirecting...' with a meta-refresh to /.

**File reference:** src/routes/admin.ts
**Verification:** grep 'DELETE ALL CONFIG' src/routes/admin.ts exits 0

### Step 4

Rewrite handleAdminGet to dual-layer auth. New flow: (1) Load config — if null return 403. (2) Read session token via readSessionToken(request); if empty or invalid (verifySession fails), return 403 with HTML redirect suggestion to /admin/login. (3) If config.access_email is a non-empty string, call verifyOwnerIdentity(request, config, source) — if !authResult.ok, return 403 with renderAccessDenied({reason, expectedEmail: config.access_email}). (4) On success, render admin form — use authResult.identity.email when CF Access was checked, otherwise config.access_email or 'admin'. Remove the old mandatory-JWT-only path entirely.

**File reference:** src/routes/admin.ts:69-117
**Verification:** grep 'verifySession' src/routes/admin.ts exits 0; grep 'access_email' src/routes/admin.ts exits 0
