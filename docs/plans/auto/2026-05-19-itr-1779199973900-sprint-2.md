# Sprint Plan: Visual + UX polish — accent, homepage, hints, wording, login

**Sprint ID:** ITR-1779199973900-sprint-2
**Spec:** [2026-05-19-final-checkpoint-human-acceptance-of-v2-migration-remediation-1.md](docs/specs/auto/2026-05-19-final-checkpoint-human-acceptance-of-v2-migration-remediation-1.md)
**Confidence:** 0.88

## Context

G9 remediation sprint 2: all 10 UX/visual issues were fixed in sprint 1 (commit a91aa96). This sprint completes the required login-redirect flow: access.ts must redirect unauthenticated /admin requests to /login?next=/admin, and the /login POST handler must honour the next param so the browser lands back on /admin after authentication. Two new integration tests validate the round-trip.

## Risk flags

- RF1: login.ts POST handler currently redirects to an absolute URL (https://example.test/) but test (g) asserts Location === '/admin' (relative). Ensure the sanitizeNext path returns the relative path directly as the Location header value, matching what the test expects.

## Task T-1: Wire login redirect: access.ts → /login?next=, login.ts handles next param

**Type:** code (modelTier: 2)

**Files to modify:**
- src/auth/access.ts (workspace: primary)
- src/routes/login.ts (workspace: primary)
- src/views/login.ts (workspace: primary)

### Step 1

In src/auth/access.ts, inside requireAdminAuth, change the no-session 303 redirect from `/admin/login?next=${next}` to `/login?next=${next}`. The existing variable `next` is already built with encodeURIComponent. Change only the Location string — no other logic changes.

**File reference:** src/auth/access.ts
**Verification:** grep -n 'Location.*login' src/auth/access.ts should show /login?next= not /admin/login

### Step 2

In src/views/login.ts, add `next?: string` to the LoginFormProps interface and render a hidden field when it is set. Inside the `<form>` block (after the opening `<form method="POST" action="/login"` line), add: `${opts.next ? `<input type="hidden" name="next" value="${escapeAttr(opts.next)}">` : ''}`. The `escapeAttr` import already exists in the file.

**File reference:** src/views/login.ts
**Verification:** grep -n 'next' src/views/login.ts should show the hidden input

### Step 3

In src/routes/login.ts handleLoginGet, extract the `next` query param from the URL and pass it to renderLoginForm. Add after the function signature opens: `const url = new URL(_request.url); const nextParam = url.searchParams.get('next') ?? undefined;`. Change the return statement to `return new Response(renderLoginForm({ next: nextParam }), { status: 200, headers: HTML_HEADERS });`.

**File reference:** src/routes/login.ts
**Verification:** grep -n 'next' src/routes/login.ts should show extraction in GET handler

### Step 4

In src/routes/login.ts handleLoginPost, add a safe-redirect helper and use it on success. Add this helper before the function: `function sanitizeNext(raw: string | null): string | null { if (!raw) return null; if (!raw.startsWith('/') || raw.startsWith('//')) return null; if (/[a-zA-Z][a-zA-Z0-9+\-.]*:/.test(raw)) return null; if (/\s/.test(raw)) return null; return raw; }`. Then read `next` from the form body: in the form-encoded branch, after reading `adminPassword`, add `const nextRaw = typeof form.get('next') === 'string' ? form.get('next') as string : null;`. In the JSON branch, add `const nextRaw = typeof body.next === 'string' ? body.next as string : null;`. On successful login, change `const rootUrl = ...` block: `const safeNext = sanitizeNext(nextRaw); const redirectTo = safeNext ?? \`${url.protocol}//${url.host}/\`;` and use `redirectTo` in the Location header.

**File reference:** src/routes/login.ts
**Verification:** grep -n 'sanitizeNext\|redirectTo' src/routes/login.ts should show both

### Step 5

Run the full test suite to confirm no regressions before adding new tests.

**File reference:** src/routes/login.ts
**Verification:** pnpm build exits 0

## Task T-2: Add two required login-redirect integration tests to login-flow.test.ts

**Type:** code (modelTier: 2)

**Depends on:** T-1

**Files to modify:**
- src/__tests__/integration/login-flow.test.ts (workspace: primary)

### Step 1

Add test (f): GET /admin without session → 303 with Location containing /login?next=%2Fadmin. Insert inside the `describe('Login flow', ...)` block after test (e). The test should: (1) call `runSetup()`, (2) call `runFetch(new Request('https://example.test/admin', { method: 'GET' }))`, (3) assert `res.status === 303`, (4) assert `res.headers.get('Location')` contains `/login?next=` and contains `%2Fadmin` or `/admin` (URL-encoded). Code:
```typescript
it('(f) GET /admin without session → 303 redirect to /login?next=/admin', async () => {
  await runSetup();
  const res = await runFetch(new Request('https://example.test/admin', { method: 'GET' }));
  expect(res.status).toBe(303);
  const loc = res.headers.get('Location') ?? '';
  expect(loc).toContain('/login?next=');
  expect(loc.toLowerCase()).toContain('admin');
});
```

**File reference:** src/__tests__/integration/login-flow.test.ts
**Verification:** grep -n 'GET /admin without session' src/__tests__/integration/login-flow.test.ts should show the test

### Step 2

Add test (g): POST /login with valid password AND next=/admin → 303 Location: /admin. Insert after test (f). The test should: (1) call `runSetup()`, (2) POST to /login with admin_password=ADMIN_PASSWORD and next=/admin in the form body, (3) assert status 303, (4) assert Location header equals /admin exactly. Code:
```typescript
it('(g) POST /login with next=/admin → 303 Location /admin', async () => {
  await runSetup();
  const body = new URLSearchParams();
  body.set('admin_password', ADMIN_PASSWORD);
  body.set('next', '/admin');
  const res = await runFetch(new Request('https://example.test/login', {
    method: 'POST',
    headers: { 'content-type': 'application/x-www-form-urlencoded' },
    body: body.toString(),
  }));
  expect(res.status).toBe(303);
  expect(res.headers.get('Location')).toBe('/admin');
  const setCookie = res.headers.get('Set-Cookie') ?? '';
  expect(setCookie).toContain(SESSION_COOKIE_NAME);
});
```

**File reference:** src/__tests__/integration/login-flow.test.ts
**Verification:** grep -n 'POST /login with next=/admin' src/__tests__/integration/login-flow.test.ts should show the test
