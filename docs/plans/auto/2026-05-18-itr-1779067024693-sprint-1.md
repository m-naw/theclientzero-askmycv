### Step 3

Create docs/specs/auth-surface.md. The file must contain both literal strings `admin_password_hash` and `cookie_signing_secret`. Write a concise spec document:
```markdown
# Auth Surface

Documents the KV keys and signing secrets used by admin authentication.

## KV Keys

### `admin_password_hash`
Stores the bcrypt hash of the admin password (cost ≥ 12). Set during POST /setup when the `admin_password` form field is submitted. Never stored in plaintext. Read by POST /admin/login to verify the submitted password via `verifyPassword()`.

### `cookie_signing_secret`
A 32-byte random hex string used as the HMAC-SHA256 key for signing `askmycv_admin_session` cookies. Created lazily on first login by `getOrCreateSigningSecret()` in src/auth/session.ts. Must be rotated to invalidate all existing sessions.

## Session Cookie

Cookie name: `askmycv_admin_session`  
Signature: HMAC-SHA256 over `payload.base64url` using `cookie_signing_secret`  
Attributes: HttpOnly, Secure, SameSite=Lax, Path=/admin, Max-Age=604800 (7 days)

## CF Access (Optional)

When `config.access_email` is non-empty, GET /admin and POST /admin/save additionally require a valid `cf-access-jwt-assertion` header. When `access_email` is empty, session cookie alone is sufficient (session cookie only — no JWT required).
```
